# 草稿格式

`草稿.md` 由 Codex 撰寫，經 Claude 審查、再由 Codex 依審查意見修正後存為 `定稿.md`，兩者格式相同。檔案分成兩部分：

- **關鍵數字**：一段 JSON。`工具/check.py` 用它檢查草稿，`工具/render.py` 用它畫結論卡、情境圖和事件表。
- **正文**：固定的章節。報告產生器會在指定章節自動插入圖表。

## 數字的分工

- 現價、歷史股價、財報實績、籌碼和市場資料都來自 `資料/`。正文引用這些數字時，要和 `資料摘要.md` 一致。
- 腳本已經會畫的圖不用再寫成表格，例如股價走勢、法人買賣超、月營收。正文只需要解讀。
- 漲跌幅、含息報酬、期望價、上下檔比和機率加權結果，由程式依關鍵數字計算，正文不用手算。需要提到時，寫成「見情境表」。
- 研究者自己的判斷只寫在關鍵數字裡，例如合理區間、情境價格、機率、事件影響和季預估，正文說明依據。

## 關鍵數字

正文第一個章節是 `## 關鍵數字`，裡面只放一個 ```` ```json ```` 區塊：

```json

  "代號": "8936",
  "名稱": "國統",
  "類型": "個股",
  "研究日": "2026-11-19",

  "合理區間": {"低": 40.0, "高": 52.0, "方法": "未來 4 季 EPS 3.20 元 × 本益比 12.5～16.3 倍"},
```

| 欄位 | 規則 |
| --- | --- |
| `類型` | `個股`、`股票ETF` 或 `債券ETF`，和 `標的/` 文件一致 |
| `現價` | `資料/` 中最新的收盤價與日期 |
| `合理區間` | 今日的合理價區間，`低` ≤ `高`。`方法` 寫出主要算式；用本益比時寫成「EPS 3.20 元 × 本益比 12.5～16.3 倍」，程式會驗算乘積是否等於低、高價 |
| `情境` | 只有 `12個月`，下分保守、中性、樂觀。價格是期末的除息後市價，必須保守 ≤ 中性 ≤ 樂觀；機率是 5 的倍數，合計 100，代表該情境的基本面假設成真的可能性。機率要依這一檔的狀況判斷，不要套用固定比例 |
| `機率說明` | 選填。`check.py` 會用近 2 年股價波動推算「歷史基準機率」，也就是只看波動、假設不漲不跌時，股價落在各情境的機率。任一情境的機率和基準差超過 15 個百分點時必填，寫明為什麼判斷不同；報告的情境表會並列兩者 |
| `配息` | 該期間內預估每單位可領的現金，沒有就填 0。程式會用它計算含息報酬 |
| `評等` | `籌碼`、`市場` 填 `偏多`、`中性` 或 `偏空`。ETF 和債券 ETF 不看個股籌碼，`籌碼` 改看資金流向，也就是流通單位數的變化。評等只說明時機與短期風險，不影響合理區間、情境價格與機率 |
| `季預估` | 只有個股要填，列出未來 8 季。`營收` 單位為億元，`毛利率` 為百分比，`EPS` 分三種情境 |
| `事件` | `狀態` 為 `已發生` 或 `預期`；`已發生` 的事件 `機率` 填 100。`影響` 是對中性合理價的百分比變動，負數代表不利。`情境` 填該事件主要歸屬的情境 |
| `檢查點` | 研究日後 12 個月內可觀察的里程碑，至少 2 項，其中至少 1 項在 6 個月內。`日期` 寫成 YYYY-MM，`預期` 寫中性情境的預期值與落後的門檻，`落後時` 寫要怎麼調整。寫法見研究方法 |
| `重估條件` | 至少 3 項 |
| `資料缺口` | 缺少的資料，沒有就填空陣列。每項都要有 `項目`、`影響`，以及 `可查`、`影響結論` 兩個 true／false：公開資料查得到才填 `可查: true`，例如法說簡報、公告；非公開的共識、內部數字填 false。只有兩者都是 true 的項目會觸發一次補查，其餘只列在報告的限制 |
| `結論` | 一句話，寫給要做決定的人看 |

## 正文章節

依類型使用以下二級標題，順序固定。標題要完全相同，報告產生器靠標題決定圖表要插在哪裡。

| 個股 | 股票ETF | 債券ETF |
| --- | --- | --- |
| 關鍵數字 | 關鍵數字 | 關鍵數字 |
| 結論 | 結論 | 結論 |
| 財報與法說 | 規則與成分股 | 基金規則與持債 |
| 籌碼 | 近 6 個月重大消息 | 利率與匯率 |
| 市場健康度 | 市場健康度 | 近 6 個月重大消息 |
| 估值 | 估值 | 估值 |
| 情境與事件 | 情境與事件 | 情境與事件 |
| 風險與重估 | 風險與重估 | 風險與重估 |
| 限制 | 限制 | 限制 |
| 來源 | 來源 | 來源 |

- **易讀優先**：每個章節先用 3～5 個條列重點寫出判斷，再補充必要的說明。每個章節約 300～600 字，`估值`、`情境與事件` 最多約 900 字。細節數字放進表格，不要寫成長段落；腳本已畫成圖表的資料只寫解讀。
- `結論` 用 3～5 個重點說明判斷和主要理由。有上次報告時，在最後加一段「和上次比較」，說明哪些判斷改變了、為什麼，並逐項說明上次的檢查點已達成、落後或尚未到期。
- `情境與事件` 說明三情境的假設，以及機率怎麼來。事件影響表由程式產生，正文只需要解釋最關鍵的 2～3 個事件。
- `限制` 列出資料缺口、代理值和最沒把握的判斷。
- `來源` 列出 `補充資料.md` 中實際用到的資料，附網址與日期。`資料/` 的來源由程式自動列出，不用重複。
- 正文可以使用段落、清單、表格、粗體和連結。不要使用 HTML。
