# 審查清單

給背景執行的 Claude（審查者）使用。審查者核對 Codex 寫的 `草稿.md`，找出程式驗不出的錯誤：數字是否有出處、推論是否合理、敘述和數字是否一致。輸出兩個檔案：

- `審查.md`：審查意見與結論
- `定稿.md`：修正後的版本，格式和草稿相同，見[草稿格式](草稿格式.md)

## 步驟

1. **先看資料，再看結論**：讀 `資料摘要.md` 和 `補充資料.md`，再讀 `草稿.md`。
2. **核對數字**：挑出最影響結論的 5～10 個數字，例如現價、近四季 EPS、本益比區間、法說財測、殖利率、主要持股權重，逐一對照 `資料摘要.md`、`資料/*.json` 或 `補充資料.md` 的出處。找不到出處或數字不符，就是錯誤。
3. **檢查推論**：
   - 合理區間的算式是否成立，使用的倍數或殖利率是否有依據
   - 三情境的假設是否和財報、籌碼、市場狀態一致；機率分配是否合理，例如市場偏弱時，保守情境的機率不應過低
   - 6 個月與 12 個月的價格路徑是否合理，配息是否只計一次
   - 事件的機率與影響方向是否合理，有沒有重大事件被遺漏
   - 籌碼與市場評等是否和資料相符
   - 有上次報告時，「和上次比較」是否說清楚變化原因
4. **檢查寫法**：正文沒有和關鍵數字矛盾的數字；沒有手算的報酬率；結論一句話能讓人做決定；沒有個人持倉、帳戶或可識別資訊。
5. **產出定稿**：以草稿為底稿修正。可以直接修改數字、機率、敘述與章節內容，但要在 `審查.md` 記錄修改了什麼、為什麼。

## 退回或自行修正

| 情況 | 處理 |
| --- | --- |
| 方向性錯誤：估值方法用錯、關鍵數字大量錯誤、漏掉決定結論的重大事件，修正等於重寫 | 第 1 輪可以退回 Codex，在 `審查.md` 寫「結論：退回」，**不需要**產出定稿 |
| 其他問題：個別數字錯誤、依據不足、敘述不一致、機率不合理 | 自行修正，產出定稿，寫「結論：通過」 |
| 第 2 輪審查 | 不可退回，一律自行修正並產出定稿 |

## `審查.md` 格式

```markdown
# 審查：<代號> <名稱>

- 結論：通過
- 輪次：1
- 核對數字：8 個，相符 7 個、修正 1 個

## 意見

### 1［阻擋］近四季 EPS 加總錯誤
- 位置：關鍵數字「合理區間」、估值章節
- 問題：……
- 依據：資料摘要「單季財報」
- 處理：已在定稿修正為 ……

### 2［建議］……
```

意見分成三級：**阻擋**（數字或出處錯誤、結論會改變）、**應修**（依據不足、敘述不一致）、**建議**（可讀性）。阻擋與應修都必須在定稿中處理。
