# 審查流程

審查者核對研究者交付的草稿。程式驗不出的錯誤由審查者負責找出：數字是否出自來源、時點與口徑是否對齊、假設是否有依據、敘述是否和數字一致，以及是否符合研究規則。審查者不修改研究資料，只寫審查意見；須修正時交回研究者，複核通過後由審查者發布。

工作夾、交接檔與狀態的定義見[研究流程](研究流程.md#工作夾與交接)。

## 找到待審草稿

我只說「審查」加上代號或主題時，在 `.tmp/工作/` 找名稱含該代號或主題、且日期最新的工作夾。只處理狀態為 `待審查` 或 `待複核` 的工作夾。`待複核` 時只檢查研究者的回覆、修正內容，以及修正可能影響的數字和敘述。找不到，或有多個工作夾同時符合時，列出候選項再請我確認。

## 審查步驟

1. **機械驗證**：執行 `validate`，檢查研究資料或更新資料能否通過；再對最新草稿執行 `verify`。驗證失敗就直接列為阻擋項。
2. **獨立抽查來源**：先不看結論和交接中的判斷。從頁首指標、估值輸入與情境假設中，挑出最影響結論的 5 至 10 個數值，對照 `來源/` 的檔案或原始網址，核對數值、單位、日期與口徑。`來源/` 缺檔時才重新查詢公開資料。
3. **重點複查**：查核交接列出的未核實項目、代理值與研究者最沒把握的判斷。
4. **規則符合**：對照[加碼研究共通規則](../提示詞/加碼研究共通.md)或本次主題的提示詞，以及[研究資料格式](研究資料.md)，逐項確認必要內容齊全，包括：
   - 頁首項目齊全
   - 今日合理價、12 個月期末價與個人買入上限分開列示
   - 三情境使用同一基準價
   - 現金流只計一次
   - 重估條件含門檻與後續動作
   - 個股季度模型的範圍正確
5. **推論與一致性**：檢查以下各項：
   - 假設有依據
   - 兩種估值法的差距已揭露
   - 反證足以對照論點
   - 正文、表格與圖表沒有手寫的數字，也沒有與快照矛盾的數字
   - 增量更新沒有殘留舊時點的敘述，且 `update.thesis` 與變動相符
6. **隱私**：確認報告與研究資料沒有帳戶、持倉明細、報表網址或其他可識別資訊。

## 意見分級

| 等級 | 判斷標準 | 處理 |
| --- | --- | --- |
| 阻擋 | 數字或來源錯誤、口徑不一致而影響結論、缺少規則必要項目、隱私外洩 | 修正並經複核後才可發布。雙方意見不一致時暫停發布，由我決定 |
| 應修 | 依據不足、揭露不完整、敘述與數字不一致，但結論方向不變 | 研究者修正，或寫明不修理由 |
| 建議 | 可讀性、呈現方式或補充觀察 | 研究者自行決定 |

## 審查紀錄

意見寫在工作夾的 `審查.md`。複核時在原意見下補寫結果，不另開新檔。

```markdown
# 審查：2026-11-19-8936加碼研究

- 審查者：Claude Code
- 審查日期：2026-11-19
- 審查草稿：草稿/2026-11-19-8936加碼研究.html
- 結論：需修正（阻擋 1、應修 2、建議 1）

## A1［阻擋］第三季稀釋 EPS 與財報不符

- 位置：`input.eps_2026q3`、分析區「股價反推」
- 問題：……
- 依據：來源 ID、檔名與頁碼
- 建議修正：……
- 回覆：（研究者填寫：已修正，或不修正及理由）
- 複核：（審查者填寫：通過或仍需修正）
```

## 結束審查

- **可發布**：沒有阻擋項，應修項也都已修正或附有可接受的理由。依交接檔的發布指令發布並執行 `verify`，在交接檔填入報告路徑，狀態改為 `已發布`。沒有任何意見時，也要在 `審查.md` 寫出審查範圍與結論。
- **須修正**：有未解決的阻擋項或應修項時，把狀態改為 `待修正`。
- **意見不一致**：研究者不同意阻擋項，複核後仍無法取得共識時，暫停發布，列出雙方理由請我決定。
- 在對話中回報結論、各級意見的數量，以及報告或 `審查.md` 的路徑。
