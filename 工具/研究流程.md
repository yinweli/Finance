# 研究流程

研究助理查核證據、決定假設並解釋結果。報告先產出草稿，經另一位助理依[審查流程](審查流程.md)核對通過後，由審查者發布。使用[研究資料格式](研究資料.md)交給本機工具計算、驗證及輸出。依任務載入共通規則、標的研究重點及必要的官方 Skill。

## 選擇研究方法

| 研究工作 | 主方法 |
| --- | --- |
| 首次完整研究股票 | `initiating-coverage`，按研究問題支援估值或預測 |
| 新財報、法說或指引 | `earnings-deep-dive`，說明公告如何改變投資論點 |
| 把新實績併入既有模型 | `equity-model-update`，核對公式、實績、估計及差異 |
| 定期追蹤投資論點或風險 | `thesis-tracker`，檢查既有證據、反證、觀察日期及重估門檻 |
| 重新設計情境或敏感度 | `scenario-sensitivity-generator` |
| 財報口徑需整理、重大模型重建或對外審閱 | 依序對應 `financials-normalizer`、`model-audit-tieout`、`deck-report-qc`，按需選用 |
| 股票 ETF | 採官方 ETF／指數研究視角，由 Finance 標的規則決定成分股估值、配息、追蹤及幣別口徑，依問題選情境、追蹤或資料整理 Skill |
| 債券 ETF、生活支出、退休準備 | 採對應的 Finance 提示詞。00679B 使用利率、存續期間、凸性、匯率及現金流模型 |

公開股票研究以[官方入口](https://github.com/openai/plugins/blob/main/plugins/public-equity-investing/skills/public-equity-investing/SKILL.md)與[路由](https://github.com/openai/plugins/blob/main/plugins/public-equity-investing/shared/plugin-routing-playbook.md)為準。依問題選一個主 Skill，再按官方要求載入支援模組。實際使用時記錄 Skill 及套件版本。研究的交付物為單一離線 HTML。

### Codex 與 Claude Code

- 在 Codex 桌面版的 Plugins 或 CLI 的 `/plugins` 搜尋 **Public Equity Investing**。CLI 可使用 `codex plugin add public-equity-investing@openai-curated`。安裝後開啟新工作階段，選取 `@public-equity-investing` 或已安裝的對應 Skill。套件和資料的實際權限視帳號、工作區和環境而定。[OpenAI Plugins 指南](https://learn.chatgpt.com/docs/plugins)
- Claude Code 透過 `CLAUDE.md` 匯入 `AGENTS.md`。Public Equity Investing 官方發布的是 Codex 套件。Claude Code 以及無法使用 Plugin 的 Codex 可採下列備援。官方套件由原發布管道維護。[Claude Code 專案規則](https://code.claude.com/docs/en/memory)
- **備援**依研究問題和資產類型選 Finance 規則，直接查原始公告、財報、行情或指數資料。先對齊日期和口徑，再整理實績、假設、估值與獨立交叉核對。列出情境、證據限制、投資論點、反證和可觀察的重估條件。股票 ETF 用成分股與指數資料，債券 ETF 用債券利率與現金流。股票或股票 ETF 的備援快照以 `method.mode` 記為 `fallback`，交代實際可用資料。若關鍵資料缺失，限縮可支持的結論並標明缺口。
- 研究只取本次必要且已授權的唯讀資料。先採公開正式資料，再按需選已授權的來源。保留來源日期和口徑。禁止自動交易、下單或自行啟用付費服務。

## 控制用量

模型每次回應都會重送整段對話，用量大約等於「回應次數 × 對話長度」。研究時用下列規則壓低這兩項。發布前的瀏覽器檢查不受這些規則限制。

- **固定資料**：收盤價、本益比、除權息、季度損益、月營收，以及 ETF 淨值與持股，先用[固定資料抓取](#固定資料抓取)工具取得，模型只讀工具輸出的摘要。工具不涵蓋的資料，例如法說、契約、指數規則和新聞，才由模型查找。
- **子代理**：預設不開。只有一項查找明顯獨立、且資料量大到會拖長主對話時，才開 1 個。子代理只拿到明確的資料清單和輸出檔路徑，不繼承完整對話；完成後只回傳摘要和檔案位置。
- **讀取方式**：網頁、API 回應、CSV 和 PDF 先存進工作夾的 `來源/`，再用程式篩出需要的欄位、列、頁或關鍵字段落，只把篩選結果帶進對話。
  - 超過約 2 萬字元的檔案不整檔讀取，例如不對大檔使用 `Get-Content -Raw`。
  - PDF 先轉成文字，再只讀相關頁。
  - 圖片只在沒有文字或表格來源時才讀。
- **不重複讀取**：已讀過的資料記在交接檔的來源對照，之後引用位置，不重讀全文。同一數值確認一次即可。
- **增量優先**：已有可重算的快照時，預設走[增量更新](#增量更新)。以下情況才做首次完整研究：沒有快照、快照無法重算，或我明確要求重做。只更新行情時，只重算估值位置和情境報酬；基本面資料沒變就不重新查找。

### 固定資料抓取

`工具/fetch_data.py` 從證交所、櫃買中心和公開資訊觀測站抓取上市、上櫃標的的固定資料，不支援興櫃。ETF 淨值與持股來自發行商，目前支援元大 ETF 和貝萊德 009826。工具會自動判斷交易所，並控制請求間隔；查詢較多季度時需要幾分鐘，可以在背景執行。

```powershell
$work = '.tmp/工作/YYYY-MM-DD-研究主題'
python -X utf8 -B 工具/fetch_data.py price --ticker 8936 --quarters 12 --work $work      # 各季末與最新收盤價、本益比
python -X utf8 -B 工具/fetch_data.py financial --ticker 8936 --quarters 12 --work $work  # 季度損益
python -X utf8 -B 工具/fetch_data.py revenue --ticker 8936 --months 13 --work $work      # 月營收
python -X utf8 -B 工具/fetch_data.py dividend --ticker 8936 --since 2024-01-01 --work $work
python -X utf8 -B 工具/fetch_data.py financial --ticker 2330 2317 2454 --quarters 4 --work $work  # 多檔共用同一份彙總表
python -X utf8 -B 工具/fetch_data.py etf --ticker 0050 --work $work                       # ETF 淨值與持股
```

- **輸出**：摘要存在工作夾的 `抓取/`，內含 `source`、`input`、`formula`，可以直接併入研究資料。每個來源用到的資料列存在 `來源/`，供審查核對。抓不到的項目列在 `missing`，並顯示在畫面上。
- **ID**：單檔查詢時不加代號前綴，例如 `close_latest`、`pe_2026q3`、`eps_2026q3`、`revenue_m202610`、`exright_20261022`。多檔查詢時加上代號前綴，例如 `2330_eps_2026q3`。
- **季度損益**：觀測站彙總表提供的是年初至該季的累計數，工具保存為 `*_ytd_*` 輸入，再用 `subtract` 公式推算單季。第 1 季的累計數就是單季數。金額單位為仟元。單季每股盈餘由累計數相減推算，期間股數有變動時，會和公告的單季數略有差異。稀釋每股盈餘、合約資產等明細仍須查閱財報。
- **除權息**：數值為「權值＋息值」，除息時就是每單位的現金分配。
- **ETF**：
  - 元大 ETF 提供 `nav`、`units`、`net_assets`，以及股票、期貨、債券的部位市值。全部持股都會轉成數值：股票有 `holding_qty_代號` 和 `holding_weight_代號`，另有 `shares_per_unit_代號` 公式，可直接用於整籃獲利；期貨和債券只提供權重。
  - 貝萊德 009826 提供 `nav` 和前幾大持股的權重，數量用 `--top` 指定，預設 20。地區與產業權重放在摘要的 `table`，需要時再自訂 ID 列入研究資料。全部持股存在 `來源/`。
  - 債券 ETF 的存續期間、到期殖利率，以及 ETF 的費用、追蹤差距，仍須查發行商的公開資料。

## 工作夾與交接

研究完成後，先在工作夾產出草稿和交接檔，經[審查流程](審查流程.md)通過後，由審查者發布到 `報告/`。我明確說不需審查時，研究者驗證後可直接發布。執行研究、審查、修正或發布時，都依下列規則決定位置與接續的狀態，不需我另外指定。

- **位置**：每次研究使用 `.tmp/工作/YYYY-MM-DD-研究主題/`，名稱與預定發布的報告檔名相同。同日已有 `已發布` 的工作夾時，依序加上 `-v2`、`-v3`。
- **內容**：

  | 檔案 | 內容 |
  | --- | --- |
  | `研究.json`／`更新.json` | 首次研究或增量更新的完整輸入，以最後送進工具的版本為準 |
  | `來源/` | 下載的公開原始資料，檔名以來源 ID 開頭。網頁與 API 回應也存一份。私人報表只在交接檔記錄分頁和範圍，不另存副本 |
  | `草稿/` | 用工作夾輸入產出的 HTML 草稿 |
  | `交接.md` | 狀態與研究說明，由研究者建立 |
  | `審查.md` | 審查意見、研究者回覆與複核結果 |

  爬取或計算用的暫存檔也可放在工作夾內。
- **狀態**：寫在 `交接.md` 第一項，依序為 `待審查` → `待修正` → `待複核` → `已發布`。研究者完成草稿時填 `待審查`。審查者發現須處理的意見時改為 `待修正`，沒有時直接發布。研究者修正後改為 `待複核`，審查者複核通過後發布，再改為 `已發布`。
- **分工**：研究輸入只由研究者修改，審查者不修改研究輸入，只寫 `審查.md`、更新狀態，並用研究者交付的輸入發布報告。研究者修正時，在 `審查.md` 每則意見下回覆「已修正」或不修正的理由。雙方對阻擋項意見不一致時，暫停發布，請我決定。
- **接續**：我只說「審查」「修正」或「發布」加上代號或主題時，在 `.tmp/工作/` 找日期最新的對應工作夾，依狀態接續。結果不明確時，列出候選項再請我確認。

`交接.md` 範例：

```markdown
# 交接：2026-11-19-8936加碼研究

- 狀態：待審查
- 研究者：Codex
- 類型：首次研究（或增量更新，基線為 `報告/…`）
- 方法：`plugin`／`initiating-coverage`／0.1.31
- 輸入：研究.json
- 草稿：草稿/2026-11-19-8936加碼研究.html
- 發布指令：`python -X utf8 -B 工具/research_report.py render .tmp/工作/2026-11-19-8936加碼研究/研究.json`
- 已發布：（發布後填報告路徑）

## 未核實項目與代理值

## 最沒把握的判斷

列 3 至 5 項，寫明影響哪些數值或結論。

## 來源檔對照

來源 ID → `來源/` 檔名、頁碼或表格位置。
```

## 首次完整研究

1. 確認代號、交易所、資產類型、研究基準日和範圍。沒有有效快照或使用者要求重做時，執行完整研究。
2. 選擇研究方法，查核官方或已獲授權的原始資料。個股與 ETF 遵守[加碼研究共通規則](../提示詞/加碼研究共通.md)及標的要求。新增標的可直接依資產類型研究，有持續使用價值的標的規則可整理到 `提示詞/`。
3. 建立工作夾與 `研究.json`，把資料時點、數值、假設、公式、來源及結論存成結構化資料，並把原始資料存進 `來源/`。
4. 驗證並產出草稿，寫好 `交接.md`，狀態設為 `待審查`。在對話中回報草稿路徑、主要結論與限制。有審查意見時依意見修正，狀態改為 `待複核`。審查通過後，由審查者執行發布指令並驗證正式報告。

```powershell
$work = '.tmp/工作/YYYY-MM-DD-研究主題'
python -X utf8 -B 工具/research_report.py validate "$work/研究.json"
python -X utf8 -B 工具/research_report.py render "$work/研究.json" --output-dir "$work/草稿"
# 審查通過後由審查者發布
python -X utf8 -B 工具/research_report.py render "$work/研究.json"
python -X utf8 -B 工具/research_report.py verify '報告/YYYY-MM-DD-研究主題.html'
```

## 增量更新

1. 按交易所、代號和主題找最新可重算快照。先擷取上次基準、重估條件和本次相關欄位。舊版 `research-data` 可擷取。沒有快照或欄位不足時，只針對有來源、日期及口徑的舊表格補建基線，缺項須重新查證。
2. 查當期可核對的行情、淨值、匯率或公告，比對有意義的變化。行情更新通常直接重算折溢價、估值位置和情境報酬。新財報、換股、重大營運事件或重估門檻若改變基本面，擴大查核，重做受影響的模型、敏感度及風險判斷。
3. 在工作夾把已核對的差異寫成 `更新.json`。保留未受影響的歷史來源和分析。檢查首頁、附註、圖表、論點與反證提到的時點和數字，說明論點維持、調整或失效的原因。
4. 合併、重算並產出新版完整草稿，寫好 `交接.md`，狀態設為 `待審查`，並在交接檔記錄基線路徑。審查通過後由審查者發布。首版命名為 `報告/YYYY-MM-DD-研究主題.html`。同日重跑或更正依序使用 `-v2`、`-v3`，原檔留存。更正說明放在 `update.changes`。

```powershell
python -X utf8 -B 工具/research_report.py latest --ticker 0050 --exchange TWSE --subject 0050加碼研究
python -X utf8 -B 工具/research_report.py extract '報告/YYYY-MM-DD-0050加碼研究.html' --field input.price --field review --field thesis
$work = '.tmp/工作/YYYY-MM-DD-0050加碼研究'
$base = '報告/YYYY-MM-DD-0050加碼研究.html'
python -X utf8 -B 工具/research_report.py update "$work/更新.json" --base $base --output-dir "$work/草稿"
# 審查通過後由審查者發布
python -X utf8 -B 工具/research_report.py update "$work/更新.json" --base $base
```

產出草稿時，`latest` 會在 `--output-dir` 中尋找基線，因此必須用 `--base` 指定 `報告/` 中的快照。發布前確認已查核來源和論點，核對圖表、表格及快照的數字，並以離線瀏覽器檢查互動和範圍較寬的表格。
